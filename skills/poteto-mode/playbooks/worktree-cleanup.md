### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `<skill-dir>/scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `~/.omp/wt/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, lock state, PR state, and the newest chat that touched it, then suggests a bucket. A locked worktree is `hold-locked`, and one whose HEAD or status could not be read is `hold-error`. The chat scan reads transcripts from `$PSTACK_TRANSCRIPTS_DIR`. When it is unset, every `LAST_CHAT` is `-` and no row is `verify-recent-chat`, so report that gap. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or the host's session list and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins. History is only a warning. Recent evidence proves activity, and no match proves nothing because the path may be implicit.
3. Verify usage before deleting. For every `verify-recent-chat` or `review` row, or anything you doubt, fan `explorer` subagents out through the active adapter to read the transcripts (`history://` or `$PSTACK_TRANSCRIPTS_DIR`) and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the host's session list. Treat missing history as unknown, never as proof of inactivity. Set each child's reasoning effort for the job through the task runner's effort setting when the host exposes it, per the Delegation section.
4. Pause on irreversible loss or protection. `wip:N` is N tracked uncommitted edits. `scratch:N` is N untracked files, not proof they are disposable. `locked:<reason>` is an intentional Git protection and always holds. Show every changed and untracked file and get an explicit decision before removing either kind, since removing a clean worktree is recoverable from its branch but uncommitted and untracked work is gone. A lock requires a separate explicit unlock decision. Clean, unlocked, merged, and proven not-in-use may proceed. `wip`, `scratch`, locked, and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
